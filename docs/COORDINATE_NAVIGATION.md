# v128 单目标相对坐标导航

状态：软件实现、离线仿真及构建通过；未烧录、未实车验收。用户报告主控3.3V轨实测4.6V，硬件修复前不进行任何通电或运动试验。

## 功能与使用顺序

目标为本次原点坐标系中的 X/Y 米数，初始车头为+X、左侧为+Y；不是相对当前车头的位移。第一版仅用于平整空旷地面，不检测障碍，不绕行，不自动恢复中断动作。

硬件修复后依次验证供电、IMU采样、安装轴向、静止校准、左右有效轮径/轮距和36:1减速比，再停稳设置原点。先按既有阶段验证轮向、停止、纠偏和转角，实测调参后才能开启坐标导航。航向P默认0，软件拒绝在P=0时启动坐标动作。

网页填写X/Y（各±5m）、巡航轮速（1–5rpm）、到达半径（0.03–0.10m，默认0.05m），主动使能后点击开始。保持页面前台并持续心跳；取消按钮、原停止按钮、失焦和手动接管均可终止。请求处理中点击开始会提示稍后重试，不排队、不自动重发。当前页面显示已接受目标的距离；刷新页面后不恢复控制权或旧目标。

## 算法与边界

转向目标 → 低速接近 → 进入到达半径 → 零目标停稳300ms → 禁止驱动。每10ms用atan2计算目标方向，用hypot计算剩余距离。转向误差小于8°且角速度小于3°/s保持300ms后进入行驶；行驶误差大于45°重新转向。航向P及角速度阻尼沿用外环配置。

线速度上限由巡航轮速与较小轮径计算，再以0.6×剩余距离减速、cos方向误差降速；线速度变化率0.05m/s²。左右轮按各自有效轮径换算；差速合成仍限10rpm（低于既有20rpm硬上限），角速度限幅和变化率沿用现有参数。进入到达半径立即置零目标，低于0.5轮rpm且角速度≤3°/s持续300ms才报告完成。停稳期间漂出半径会重新转向；总120秒时限始终有效。

转向5秒内未改善至少0.05rad，或行驶5秒内未缩短至少2mm，报告无进展并禁止驱动。低增益、极慢车或打滑可能触发失败，不能为了通过验收关闭保护。编码器/IMU断流和定位不连续退出；控制心跳300ms、电机反馈100ms、IMU50ms约束保持。完成后旧心跳不能再次启动动作。

估计半径不等于实车误差保证；里程计受打滑、轮径偏差和航向漂移影响。暂无路径搜索、障碍识别、绝对定位或指定终点朝向。

## 协议兼容

32字节导航消息格式1追加op=9，参数[x_m,y_m,cruise_wheel_rpm,radius_m,0]；会话及递增序号沿用原控制权。旧40字节运动遥测和112字节IMU遥测长度不变；IMU mode新增3转向目标/4驶向目标/5到位停稳，result新增7无进展。原op1–8保持。STM32、ESP32、桌面服务必须配套升级，旧网关会拒绝op9。此次没有重启现场桌面服务或升级设备。

## 离线验证与实车验收

`python -B tools/test.py`运行生产C算法、模拟差速运动、协议/会话/心跳及网页逻辑测试。`uv run --with playwright python -B tests/test_imu_browser.py`使用隔离服务和全部API替身验证坐标输入、心跳、缺测停车及移动布局；不会访问现场设备。

仿真CSV为理想车模型生成，明确不是传感器实测。保留各点，不平滑；六个目标包含正负X/Y、斜向及原地，独立测试重复包、范围拒绝、超时、无进展、IMU断流、心跳丢失、取消和完成后心跳拒绝。仿真未覆盖真实轮胎/地面/电机动力学，不替代实车验证。

硬件恢复后，用独立卷尺/地面坐标和角度参照，先逐阶段验证，再对单目标至少连续5次保存全部成功/失败/停止数据。保持原1米误差≤10cm、90°误差≤5°标准，不能用内部估计证明精度。
