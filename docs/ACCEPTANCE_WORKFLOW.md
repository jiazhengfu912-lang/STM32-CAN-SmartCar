# 每轮修复的验收证据

用户要求：修复不仅要有文字结论，还必须有原始实测波形，使修改方向可直观看到。

每轮记录以下内容：

1. 修改前的问题、证据和预期改善；准确固件版本及实际P/I、测速方法、启动策略，不把不同构建统称一个版本。
2. 硬件条件（架空/落地、供电、网络）、目标速度、方向、试验时长及操作顺序。零目标观察和真实运动分别记录。
3. 停止后立即导出CSV或诊断JSON，包含启动、运行、停止、故障和缺测；在控制台重启或下一轮覆盖前存到本轮独立目录。不要仅保存均值/峰值，也不要只留下最好的一轮。
4. 原样快照及SHA256；数据不完整时说明缺失区间。原始输入只读，统计或绘图不得改写输入。不要把配置令牌/密码放进报告。
5. 逐点绘制目标与左右实际速度、控制输出、状态/故障/错误计数。长缺口断线，禁止为了图形好看删除异常点、额外平滑或补造样本。若展示滤波值、派生值，明确算法和窗口，同时保留可用的原始字段作对照。
6. 修改前后用相同工况、坐标尺度展示；若测量方法改变，要明确标注，不能把显示更平滑直接当作机械性能改善。波形保留起步超调和停止过程，不只截取稳态。
7. 在 `docs/ACCEPTANCE.md` 对应版本正文中直接嵌入波形PNG（`![说明](相对路径.png)`），不能仅提供图片链接或另一个索引。图旁必须写P/I修改前→修改后（未改也明确写出）、积分周期/单位约定、是否修改算法、具体策略与原因，以及该图证明的改善和遗留问题；图片本身也标注版本、实际P/I及算法。保留SVG、原始数据和统计链接，区分构建通过、安装成功、通信成功和实物验收；把未通过、异常中断、尚待验证写清楚。

## 绘图

仅离线读取文件，不连接设备，不产生运动命令。首次安装绘图库：

```powershell
cd D:\STM32-CAN-SmartCar
python -m venv out/plot_env
.\out\plot_env\Scripts\python.exe -m pip install -r tools/requirements-plot.txt
```

每轮先将真实CSV存好，再指定版本与**新的独立输出目录**：

```powershell
.\out\plot_env\Scripts\python.exe tools/plot_acceptance.py --csv out/tuning_v119/repeats.csv --version 119 --output docs/evidence/v119-round1
```

上面119只是后续用法示例，不代表该版本已存在或已验收。工具会原样复制输入到raw、记录SHA256、生成全部识别到的运动段图和故障图；统计不自动等于验收通过。CSV需使用当前控制台导出的字段。

重建本次历史补档：

```powershell
.\out\plot_env\Scripts\python.exe tools/plot_acceptance.py --output docs/evidence/2026-09-19
```

这是历史资料补绘，不补跑硬件、不证明尚未测试的工况。诊断JSON图由脚本的历史补档模式读取对应已知格式；新增格式需要先核对字段，再扩展绘图。
