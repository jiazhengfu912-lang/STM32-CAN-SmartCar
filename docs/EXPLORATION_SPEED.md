# 自主探索效率优化与复现

本轮针对小场景中短距离目标、反复转向和目标之间固定等待的耗时进行优化。探索器仍只向Nav2提交目标；继续使用SLAM Toolbox、NavFn A*和RPP，建图运动上限仍为0.20m/s、±0.35rad/s，停车保护和STM32 PI未改，也未运行实车。自主探索新增专用SLAM匹配配置；手动建图和已知地图导航不加载该配置。

文中的v1—v6是本轮探索策略/配置编号；STM32固件源码仍为v131。

## 策略

- 对候选观察点，从当前在线地图估计3m内未知区观测收益。72条射线以半个地图栅格为步长，遇到已知障碍或地图边界停止，不把已知墙后的未知计作可见收益。该值是期望收益，不是真值面积或覆盖证明。
- 用预计路程时间、起步转向时间及目标交接开销摊销收益；同一长前沿保留多个候选位置，减少只看最近代表点造成的低收益短目标。
- 当最佳预估收益至少3m²时，优先选择收益至少2m²且不低于最佳60%、路程至少1.2m的观察点；剩余收益较小时按收益/时间补盲，保留原最小0.8m前沿与短距离目标，受阻与完全没有前沿继续分别记录。
- 360度雷达无需到达每个目标后再对准前沿，目标朝向改为估计到达切线。Nav2依然按原位置和角度容差检查到达，没有扩大容差。
- 目标执行期间保持目标稳定。结束后最少等待0.2仿真秒并收到新的地图，再选下一个目标，替代固定等待3秒。地图/时钟/扫描/里程计或任务心跳异常仍停车。
- 已知自由区四邻接搜索改为原生列表队列，减少逐栅格NumPy标量开销；安全通行圆0.37m、观察圆0.40m、禁止穿越未知/墙体及失败目标记忆保持。
- 在同一前沿的候选中，优先使用0.65m已知自由余量的观察点，减少地图更新和到达误差造成的贴障/提前结束；没有更宽余量时仍允许原0.40m合法候选，不降低通行保护或丢弃窄处补盲。
- 远行前检查附近独立前沿：若现在顺路观察的额外代价明显小于离开后的返回代价，先补这一小片。两观察点之间的连接沿安全广搜树计算，不能用穿墙直线虚构便宜路线；这是有限前瞻启发式，不承诺全局最短路。

## 地图质量和导出

开发轮次曾出现SLAM估计在约0.1秒内平移约1.1m、实际小车只移动几毫米的现象。被动真值与里程计记录支持“定位修正突跳”，尚不能仅凭此断定是闭环或局部匹配中的哪一条约束。自主探索加载`exploration_slam.yaml`，保留闭环，增加闭环候选链长度、提高粗/细匹配响应要求、降低粗匹配方差上限，并启用Huber损失抑制异常约束。参数用途和Humble 2.6.10支持见[SLAM Toolbox说明](https://github.com/SteveMacenski/slam_toolbox)及[该版Ceres求解器](https://github.com/SteveMacenski/slam_toolbox/blob/2.6.10/solvers/ceres_solver.cpp)。这属于本轮联合优化，不能把全部结果归因于前沿策略，也不保证消除所有定位错误。

随后对v5保存的扫描及原始轮式位姿做确定性离线重放，复现271.5秒和327.5秒的闭环及相同最终占据格/P95偏差；两次细响应分别约0.734和0.724，超过当时0.65门槛。禁闭环消融与保留闭环、提高细响应门槛至0.80的重放都消除了这两条错误关联，P95从约0.426m降至0.061m。因此最终配置保留闭环并采用0.80。重放只覆盖已保存轨迹，正式结果仍以修改后新启动的重复仿真为准；更严格匹配也可能漏掉真实闭环，陌生大环境仍须独立验收。

另外修正自动地图导出的阈值：三值PGM中的未知灰度205，配合原`free_thresh: 0.25`会被Nav2重载为自由区；改用0.196保留未知。`verify_map_export.py`使用独立Nav2地图服务器逐格核对实际重载值、分辨率和原点，避免仅凭文件存在就判定导出成功。该修复用于自动探索导出；历史证据和手动保存工具保持原样，旧地图需另外验证，不能推断它们已自动修复。

## 用户启动

先退出旧启动，再从仓库根目录执行：

```bash
bash ros2_ws/tools/build.bash
source ros2_ws/tools/env.bash
ros2 launch smartcar_nav2 exploration.launch.py \
  world:=discovery_lab rviz:=true headless:=true max_sim_seconds:=1800
```

Gazebo在后台运行，RViz显示实时建图。需要同时看到Gazebo窗口时改为`headless:=false`；两个图形窗口会影响虚拟机墙钟耗时。无需键盘、初始位姿或人工导航目标。[新场景完整验收](DISCOVERY_LAB_ACCEPTANCE.md)及[暂停/结束保存](AUTONOMOUS_MAPPING.md)沿用。

## 比较方法

优化前源码冻结在独立工作空间，前后使用相同物理场景、空白SLAM起点、900仿真秒预算、运动上限和无界面配置；每次独立ROS域与Gazebo分区，顺序运行，原始CSV、地图逐帧栅格、目标结果、故障和缺测全部保留。

离线把SDF物理场景中与出生点连通、具0.37m安全余量的机器人中心区域作为固定参考分母，记录其被SLAM观测为自由区的比例，以及连续3次真实地图更新达到80%/90%/95%的首帧时间；不插值、不拟合坐标，也不把该几何提供给探索器或SLAM。同时比较累计路程/转角、停等、目标数、地图占据格到场景表面的距离及停止/保存结果。单次面积增长和预估收益不能代替地图质量或完整覆盖。

`DONE`仍只表示任务已结束保存，`NO_FRONTIERS`及`complete=true`还需配合人工检查；预算、受阻与提前结束仍保存部分图。该指标用于选定仿真场景的前后比较，不能证明任意环境或实车一定更快。

## 实测结果与边界

相同900仿真秒预算、空白起点和原运动边界，两轮基线95%观测指标为262.950/480.267秒，最终v6为123.760/105.090秒，均值371.608→114.425秒（减少69.2%）。三帧确认的固定参考机器人中心区观测比例不等于全图完成或准确率；最终两轮都标记`NO_REACHABLE_FRONTIERS_PARTIAL`，不能说成自动完成整图。末图几何代理P95约0.065/0.064m，预定门槛0.15m，两轮0.15m内占据格比例均100%。

任务部分结束均值558.464→346.659仿真秒，平均目标25→10、累计转角87.342→45.466rad、近静止93.320→23.676秒；里程计路程32.287→42.462m，第二轮长途补盲使路程增加。因此本策略没有保证全局最短路线或任意环境更快。全部早期失败、提前结束和中断与正式结果一并保留。

办公室另测一对：95%观测指标442.327→114.972秒（减少74.0%），任务部分结束752.538→712.894秒（减少5.3%），尾段长途补盲仍明显。最终参考观测93.198%→100%，在线末图P95约1.071→0.076m，实际PGM约0.080m；不混入实验室两轮均值，不宣称任何环境或所有路线都更快。

最终版本通过任务进程冻结后停车锁存、进程恢复不自动续行、显式继续/暂停/结束保存，以及可观测房间自动`NO_FRONTIERS`结束。完整速度、逐帧地图质量、原始数据与全部失败见[最终报表](evidence/exploration-speed-20261021/README.md)和[验收正文](ACCEPTANCE.md)。

最终新图在独立AMCL启动中完成一次短距离目标导航并持续停车；真实Nav2地图服务器对三张最终导出图逐格重载检查通过，未知格分别2624、2349、2596，均完整保留。实验室实际PGM几何P95约0.070/0.060m，办公室约0.080m，均按同一门槛另验，避免用在线末帧代替交付图。
