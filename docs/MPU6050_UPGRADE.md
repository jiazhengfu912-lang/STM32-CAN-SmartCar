# MPU6050 与相对定位升级说明（v127）

日期：2026-09-20。当前交付为软件实现与离线验证；未烧录、未重新连接设备、未执行运动。P0主控恢复和P1–P5实物验收均未完成。v125的低速二次起转问题未修改或宣称解决。

## 接线与初次启用

| 模块 | STM32 | 要求 |
|---|---|---|
| VCC | 按模块输入规格供电 | 先确认模块支持3.3V输入及稳压器压降 |
| GND | GND | 共地 |
| SCL | PB10 / I2C2 | 外部上拉至3.3V，检查模块已有上拉 |
| SDA | PB11 / I2C2 | 外部上拉至3.3V |
| AD0 | GND | 7位地址0x68 |
| INT、XDA、XCL | 不接 | 第一版定时读取 |

模块牢固安装；车体X向前、Y向左、Z向上。实际安装不一定与模块丝印同向，网页安装方向填有符号传感器轴编号。例如X取传感器Y、Y取传感器-X、Z取传感器Z时填`2,-1,3`；程序拒绝重复轴、左手映射。

上板顺序：先恢复主控通信并确认停机保护，再更新兼容网关及App，保持电机不运动检查原始IMU；确认安装方向→静止校准5秒→输入实测几何参数→双轮反馈新鲜且停稳后设原点。任何设置都不会自动使能。

所有新增参数只保存在STM32 RAM，每次重启必须重新配置和校准。网页输入框只是待发送值，接受请求仍须核对设备状态，不能把默认输入当作已标定值。

- 左右有效轮径：20–500 mm；有效轮距：50–1000 mm，不预填。
- 当前控制链固定电机轴/车轮比36:1。几何接口只能确认36；如果实测不符，禁止使用导航，需要同时适配原有轮速/限幅单位，不能只改里程计。
- 默认外环P=0、角速度阻尼=0，仅观察模式。直行可记录无修正基线；转90°必须先停稳配置非零P，并按阶段逐步实测调参。
- 初始角速度上限0.6 rad/s、变化率1 rad/s²，陀螺仪增量权重0.98。导航两轮目标另限10 rpm，仍位于原20 rpm保护边界内。
- 校准只在禁止驱动时执行；有轮速反馈时要求新鲜且低于轮速0.5 rpm。无电机反馈时允许电机断电校准，IMU仍需连续静止5秒；几何原点和运动必须有双轮反馈。

## 程序与故障行为

`mpu6050.c`管理初始化和事务；`imu.c`进行解码、右手轴映射与校准；`navigation.c`管理里程计、外环和动作状态。算法模块不依赖HAL，可直接使用主机编译器测试。

MPU配置：100kHz、100Hz、DLPF_CFG=4、SMPLRT_DIV=9、加速度±4g、陀螺仪±500°/s。WHO_AM_I必须为0x68。一次读INT_STATUS及其后14字节，DATA_RDY未置位不积分旧样本。实际采样间隔参与积分，不假设每拍严格10ms。

HAL保持原文件不改。驱动按当前仓库HAL `Mem_Read_IT/Mem_Write_IT` 的非等待部分设置句柄并触发START，事件/错误仍由HAL ISR处理；不调用包含25ms BUSY自旋的公共启动函数。启动检查总线和引脚，无忙等；事务5ms超时，复位I²C2并在1秒后重试。升级HAL版本时必须复核这些内部字段和`I2C_NO_OPTION_FRAME=0xFFFF0000`约定。实物总线时序及异常波形尚未验证。

主循环优先处理CAN/控制，随后处理协议和IMU。UART改用4槽持久缓冲队列，低优先级遥测最多占2槽，为控制应答留空间；发送30ms未完成中止并触发原UART故障。OTA应答仅在停稳状态有界排空后复位。

Roll/Pitch互补滤波时间常数0.5秒，0.8–1.2g之外暂停加速度修正；采用面向平地小倾角车辆的估计，非任意翻滚姿态解算。导航要求Roll/Pitch绝对值小于0.35rad。校准要求0.9–1.1g、轴加速度相对开始值变化不超过0.04g、各轴角速度绝对值不超过约3°/s，至少450样本且满5秒；外部仍需确保静止，传感器无法可靠区分所有缓慢运动与零偏。

编码器累计位置差→轮距增量→陀螺仪/轮差转角增量融合→中点航向更新XY。编码器反馈间隔达到40ms标记可能失去展开连续性；50ms新鲜度、IMU丢样/复位、校准或轴向变化均可令定位无效。失效后不自动补位移，重新停稳设原点。该方法不消除长期漂移及打滑误差。

直行在启动时锁定航向；±90°动作每个新请求只建立一次相对目标。外环P和角速度阻尼生成角速度，再转成左右轮速度；限制角速度、变化率及两轮目标。两类动作最长15秒。转角误差≤2°且角速度≤3°/s持续300ms后禁止驱动；零电流是滑停，不是机械抱闸。

运动中IMU数据年龄达到50ms或定位不连续：故障5（IMU/定位依赖失效），退出导航、清零驱动。显示模式下传感器异常不影响原手动控制。传感器恢复后不自动恢复导航。300ms用户心跳、100ms电机反馈超时保持不变；普通手动速度/停止命令接管后取消导航。设备复位丢失原点、参数和动作。

## 接口与兼容

所有多字节线协议为小端，浮点为IEEE754 binary32。旧40字节运动遥测及16字节普通控制保留；旧网关没有新接口，无法执行新增功能。新网关兼容旧运动遥测，缺少IMU时返回无效，原手动控制继续使用。

### 导航请求

网页`POST /api/navigation`：`{op, args:[最多5个有限数值], owner, at:毫秒时间戳}`。校验当前页面所有权和250ms请求年龄，发送一次，无自动重试。

ESP32认证`POST /navigation`：32字节，转发STM32类型`0x41`。布局：`u8 op,u8 format=1,u16 reserved=0,u32 session,u32 sequence,float args[5]`。应答沿用`0x71`控制应答格式。

| op | 操作 | args |
|---|---|---|
| 1 | 静止校准 | 空 |
| 2 | 停稳设原点 | 空 |
| 3 | 直行保持 | 带符号车轮rpm，绝对值1–10 |
| 4 | 相对转角 | +90或-90度 |
| 5 | 几何参数 | 左轮直径m、右轮直径m、轮距m、减速比36 |
| 6 | 外环/融合参数 | P(0–5)、阻尼(0–2)、角速度上限(0–1]rad/s、变化率(0–2]rad/s²、陀螺仪权重[0–1] |
| 7 | 轴映射确认 | 3个有符号轴编号 |
| 8 | USB诊断流 | 0关闭、1开启；只能在禁止驱动时切换 |

普通`/api/control`新增op=4导航心跳，左右目标必须为0，复用当前session及递增sequence。ESP32只转发本次收到的UDP包；STM32续租现有动作，不重置目标。普通op=2取消导航，op=0始终停止。内部导航计算从不更新`command_ms`。停止、超时、到位、故障后，旧心跳无法重启动作。

### IMU消息

STM32类型`0x12`、载荷112字节；常规10Hz，USB诊断模式50Hz。

| 偏移 | 类型/长度 | 内容 |
|---|---|---|
| 0 | u8 | format=1 |
| 1 | u8 | bit0采样新鲜、bit1位置有效、bit2定位不连续、bit3几何已设、bit4轴向已确认、bit5倾角已初始化 |
| 2,3 | u8×2 | 校准状态(0未校准/1进行中/2成功/3失败)、动作模式(0无/1直行/2转角) |
| 4,8,12 | u32×3 | 发送时刻、采样时刻、采样序号 |
| 16 | i16×7 | ax,ay,az,temp,gx,gy,gz原始计数，传感器坐标 |
| 30,31 | u8×2 | 动作结果、诊断开关 |
| 32 | float×7 | roll,pitch,yaw,x,y,heading,去零偏gyro_z；单位rad/m/rad/s |
| 60 | u32×8 | I²C错误、超时、采样缺口、最大控制间隔ms、最大采样间隔ms、控制>12ms次数、UART丢帧数、原点代次 |
| 92 | i16×6 | 目标LR、速度LR、输出LR（原电机轴rpm及电流单位） |
| 104,105,106,107 | u8×4 | 驱动状态、故障、WHO_AM_I、保留 |
| 108 | u32 | 固件版本 |

动作结果：0无、1运行、2到位、3取消、4传感器失效、5动作超时、6驱动退出。

ESP32 `/telemetry`在原字段后增加`imu_wire`（224字符十六进制）、`imu_age_ms`与`imu_transport_valid`。桌面服务解码为`telemetry.imu`；网页显示期限500ms与MCU控制期限50ms是两层不同要求。运动在线不能让旧IMU数据有效。`GET /api/imu.csv`导出网页实际轮询样本，约10Hz而非高频原始流；无效行仍保留。坐标图缺测断线，原点改变清空旧坐标系。

## 采集、带宽与证据

115200 8N1每秒约11520字节。IMU帧124字节×50Hz=6200B/s，运动帧52×10=520B/s，10Hz控制应答28×10=280B/s，身份约28B/s，基础合计约7028B/s（61%）。停车后启动诊断约2000B/s会额外占用带宽；队列超额低优先级帧可丢弃，必须检查`tx_dropped`、时间间隔和序号，不能宣称无缺测。ESP32 USB发送空间不足直接丢诊断帧，不阻塞控制，也不重传。没有在STM32新增大容量高频环形缓冲，原启动记录保留。

先建立本轮元数据JSON，写入真实硬件条件和已经由设备接受的参数，例如结构：

```json
{"version":127,"hardware_condition":"填写本轮真实供电/架空或落地/安装方向/地面/外部测量方式","nav_config":{"geometry":"填写实际值","axes":"填写实际映射","kp":"填写实际值","kd":"填写实际值","max_rate":"填写实际值","slew":"填写实际值","gyro_weight":0.98}}
```

参数占位文字必须改成真实记录。另保存`/api/control_trace`中的参数接受事件；不得把网页输入框的未发送值当成固件参数。

```powershell
# 禁止驱动时在网页开启USB诊断；采集工具本身不写串口。
python -B tools/capture_imu.py --port COM3 --seconds 60 --metadata out/本轮参数.json --output out/imu-本轮
# 只读绘图，输出目录必须是新的；输入缺测不补样。
.\out\plot_env\Scripts\python.exe tools/plot_imu.py --input out/imu-本轮 --output docs/evidence/imu-本轮
```

看到`USB reader ready`后再开始人工试验；串口不能同时被其他工具占用。10分钟静止测试使用`--seconds 600`。采集失败或提前停止也保存已有serial.bin、JSON/CSV及SHA256。绘图保存PNG/SVG；需将真实波形直接嵌入`ACCEPTANCE.md`本轮正文并标注P/I前后、外环参数与实测结论，不能仅放链接。

## 验收顺序与边界

1. P0：主控身份/版本/新鲜双轮反馈/停止保护恢复。当前未执行。
2. P1：电机不运动，IMU连续10分钟；BUSY、断连、身份错误及恢复；实测控制周期和I²C时序。主机替身不等于电气验证。
3. P2：安装方向和手动三轴旋转，5秒校准与失败重试；记录静止漂移。
4. P3：外环P/阻尼零值记录基线，停稳后逐步增加参数；1米直行5次，估计终点误差与真实横向偏移均≤10cm。
5. P4：左右90°各5次，独立角度测量误差≤5°；检查超调、到位滑停、超时、页面失焦及失联。
6. P5：1米定位重复和方形闭合路径，外部位置测量与融合轨迹对照；所有失败轮次保留。
