# 探索吞吐与Frontier目标交接

**效率状态：目标尚未达成。办公室记录到交接中位下降22.2%，实验室基本持平；两场景95%→98%近静止与用时均有退化，详见本轮实测结论。v17是本地待优化实现。**


当前实现为探索v17，基线是本轮冻结并独立仿真的v15。v16开发轮发生同覆盖区间的吞吐退化，数据、源码与波形全部保留，未作为最终实现。版本号指探索策略，STM32源码仍为v131、设备最后确认v127；本轮未连接硬件。

## 当前流程

每个导航动作成功后，使用最新在线地图和实际机器人位姿重新生成前沿候选，再查询实际Nav2路径。v17移除了v16跨目标复用的预备候选；不会沿用行驶前的候选子集、区域估计或旧收益。NavFn/RPP、SLAM、0.20 m/s线速度、±0.35 rad/s角速度、0.15 m位置到达容差、0.37 m通行圆和0.40 m观察余量保持。

原来横跨搜索发起、结果处理和规划派发的共享1秒节流，改为仅限制空结果重复搜索。已完成的异步计算与动作响应在下一次0.2墙钟秒状态循环中处理；不会因为上一阶段刚结束再等满1秒。行驶期间刷新生命周期就绪证据，三秒时效、显式恢复重新确认和旧目标取消屏障保持。

如果当前地图比发目标时更新、收到该图不超过1仿真秒、且全部指定未知格已经成为已知，就直接记录已有的真实观测，免除额外等一帧。任意指定目标仍未知、越界或缺失时，继续等到达后的新地图。不会用导航成功替代观测成功；分别记录目标格的已知数和已知自由数。

每批只计算一次0.40米观察安全区域，同一候选且完全相同终点的可见性可复用；每条不同路径的停车末段仍独立检查。专门回归验证同终点的另一条贴障末段仍被拒绝。发目标前继续按最新地图检查目标位置、指定目标可见性和停车末段。Nav2路径查询保持串行，并且只在当前导航动作结束后发起，避免争用正在执行的行为树规划动作。

单目标到达仍执行原Nav2收速与到达判定。探索器只发导航目标，不发速度；暂停、失联锁存、心跳恢复不续行、显式恢复和停车保存规则不变。

## 保持选点结果的计算加速

真实尾段快照剖析中，一次搜索调用了496次收益射线计算和12次安全广搜。v17只缓存与地图内容无关的射线偏移模板，保持半格采样、360射线收益估计和原运算顺序；每个候选仍读取本次最新地图，不缓存旧收益或占据值。

区域聚合只需要半径3米内的四邻接距离，原实现却为每个区域搜索整张连通地图。现在区域搜索在`ceil(半径/分辨率)`步后停止扩张，再使用原半径条件判定成员；全局机器人可达性搜索仍完整运行。隔墙欧氏近点不能直接归为同一区。

对12张本轮真实地图快照独立回放，v17与原v15的全部候选、收益、排序和诊断字节一致；离线搜索用时改善约0%—22%，不同快照收益不同。该回放证明固定输入上的结果保持，不代替真实Gazebo任务吞吐。[逐快照原始结果及输入哈希](evidence/exploration-handoff-20261024/software/frontier_equivalence_v17.json)

## v16开发退化与保留依据

历史v14办公室记录的28次目标交接累计100.481仿真秒，中位数3.5755秒，其中98.773秒符合近静止判据。95%→98%区间的26.904秒近静止分别关联前沿搜索11.962秒、路径查询阶段9.073秒、等地图3.042秒、导航2.329秒、派发等待0.498秒；阶段关联不是CPU测量。[原始事件/里程计诊断](evidence/exploration-handoff-20261024/analysis/historical_v14/diagnosis.json)

v16尝试在终点附近预备下一批前沿，交接时间有改善，但本轮实验室95%→98%相对原开发参考从约94.039秒增加到231.298秒。后续发现原开发参考的编译优化等级不同，因此该数据只保留问题记录，不作v17正式性能对照。真实轨迹出现跨上下区域反复访问；不能把整场退化唯一归因于某一个字段。v17移除跨目标候选复用，恢复每次从最新地图产生完整候选，再验证等价计算加速和交接等待优化。v16实验室完整原始数据与办公室提前失败/中断（已执行4个目标、记录运动7.336米）、缺失最终地图均保留，不删除失败或以新版图替代。[v16退化记录](evidence/exploration-handoff-20261024/software/optimization_regression_v16.json)

## 衡量与复现

新增`pipeline.csv`保存真实状态阶段、地图版本、搜索/查询状态和回调墙钟间隔。`frontier_search_started/finished`是发起到结果被状态机消费的间隔，不等于CPU；在v16中也可能包含已完成的预备结果等待当前目标结束。`planning_batch_finished`记录整批查询实际间隔。原始`planning_cpu_s`字段沿用旧格式，实际是Nav2报告的`planning_time`，从未参与路线排序，派生CSV称为`nav2_reported_planning_s`。

近静止定义为原始里程计`|v|<0.02 m/s`且`|w|<0.05 rad/s`，原地转向单列。超过1仿真秒或时间倒退的间隔不补点、不推断静止。新旧版使用相同事件规则做阶段关联，不能据此声称测出了规划CPU。持续至少0.5仿真秒的近静止段是运动学统计，不自动等于控制器显式停车次数。

吞吐按固定几何参考的90%→95%、90%→98%、95%→98%区间比较，连续三次真实地图更新确认阈值。归一化参考面积吞吐是固定阈值差面积除以实测用时，不是精确新增光束面积。目标数、整场路程和结束时间只作辅助指标；更多零碎目标或更早partial不代表更快。最终已知、已知自由和几何P95分开评价。

[预设v17协议](evidence/exploration-handoff-20261024/source/protocol_v17.json)使用串行Gazebo、独立输出、ROS域和分区。最初隔离v15的CMake构建等级为空，新版为RelWithDebInfo；原办公室早期还与构建/完整软件检查重叠，原实验室有一次约0.7秒的定向单测。这两轮只作开发参考，保留全部数据；正式比较改为补跑的RelWithDebInfo匹配基线，记录编译器、编译选项和实际Nav2/SLAM参数。v17完整测试和离线回放在其运动实验之前完成；单场景一对样本只作为工程观察，不构成统计显著或实车结论。

[本轮完整证据与结论](evidence/exploration-handoff-20261024/README.md)保留所有版本、失败、缺测、逐点PNG/SVG和哈希；[验收正文](ACCEPTANCE.md)直接嵌入各轮波形。报表由`ros2_ws/tools/report_exploration_handoff.py`只读生成；输出必须使用新目录。当前采样为车体线/角速度与安全速度指令，没有实物左右电机测速或PI输出，不补造硬件数据。
